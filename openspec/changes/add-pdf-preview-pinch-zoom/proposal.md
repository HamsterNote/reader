# Proposal

## Why

PDF 版式预览需要让读者以双指放大细节，并在缩放和平移时保住正在看的内容。功能需通过 reader 预发布包交付到 WebBase，让开发者直接在宿主中预览和复测。

## What Changes

- reader 自行识别双指、计算中点锚定、处理平移和回弹，仅调用 PDF.js 的缩放渲染能力。PDF.js 自带手势实现不得参与。
- 建议手势缩放为基准版式的 1×–3×。双指中点带动原页锚点，缩回 1× 时保留焦点所在原页并恢复基准横向布局。已接管的选区手柄与宿主拖拽保留当前触点序列，双指优先于待识别的正文动作。
- 交付依次为发布 `@hamster-note/reader@3.1.0-ham414.N`、更新 WebBase 的实际安装和常规编辑器、在 WebBase 现有 `?demo=1` 入口加入一键 PDF 样例。
- 范围为使用 PDF.js 的 Web PDF Layout，包括 WebBase Web 与其原生 WebView 中的该编辑器。PDF Text、EPUB 和独立原生 PDF 浏览器沿用自身交互。

## Capabilities

### New Capabilities

### Modified Capabilities

- `pdfjs-web-reader` 增加 PDF Layout 的双指缩放、焦点、平移、回弹与输入优先级要求。

## Impact

- reader 的 `PdfDocumentViewer`、裁切视图、页面工具层、阅读位置及发包工作流。reader 当前版本为 `3.1.0-ham400.3`。
- WebBase 的宿主和 WebView 各有独立清单与锁文件。所查分支均锁定 `3.1.0-ham365.1`，集成时须按准确新版本安装并验证两套构建。
- 待评审的行为参数为 1×–3×、回弹上限 48 CSS px / 250 ms，以及下述手势优先级和 1× 落点。预发布 dist-tag 拟用 `ham414`。

## 冒烟/自测用例

开发阶段在 reader Chromium harness 验证手势，再由 WebBase Playwright Chromium 用正式编辑器入口复测。固定样例使用可定位字符的至少三页 PDF，包含原页 2 的可见标记及旋转/裁切样例。用 CDP `Input.dispatchTouchEvent` 发有稳定 ID 的触点，分帧采样，按需在触摸上下文开启触摸仿真。以 DOMMatrix、页面框、滚动量和锚点位置还原有效变换，兼顾最终由 PDF.js 重排尺寸的情况。比例容差为 0.02，焦点及落点容差为 4 CSS px，边界容差为 2 CSS px。

| 用例 | 操作步骤 | 期望结果 | 判定方式 |
| --- | --- | --- | --- |
| C1 缩放上下限 | 打开样例至 Layout 原页 2，以标记为中点，双指间距从 80 拉到 160 CSS px 后释放。从全新 1× 用例拉到 320 CSS px，另从 1× 捏至 40 CSS px | 依次稳定在 2×、3×、1×，过程中不越限 | 逐帧和稳定后断言 PDF 有效比例。宿主 `visualViewport.scale` 保持初值 |
| C2 中点跟随 | 以页内标记为中点，双指间距从 80 拉到 160 CSS px，同时中点右移 30、下移 20 CSS px。避开边界，再以同样手势复测旋转和裁切样例 | 同一原页点随中点移动，释放前后无跳动，文字及标注随页对齐 | 换算原页标记坐标，逐帧及稳定后与中点比对；现有叠层对齐测试沿用其 1 CSS px 断言 |
| C3 平移与回弹 | 在 2× 从正文空白单指平移横纵轴，再以双指固定间距移动中点。向左右边界及文档首尾继续拖过界后松手 | 已放大内容可平移，双指平移不改变倍率。超界方向有阻尼，松手后回到最近合法位置 | 内区位移跟随触点，回弹前越界大于 0 且至多 48 CSS px，松手 250 ms 内边界误差至多 2 CSS px。无宿主滚动或额外翻页动作 |
| C4 回到基准 | 在 2× 平移至原页 2 的中段，选一个远离文档首尾的标记为最终中点，捏至 1×。随后另起一指滚动 | 同一原页仍可见，恢复基准横向布局，以最后中点的安全视口 Y 对齐原页标记。普通纵向滚动恢复 | 比较原页 ID、基准页面框及锚点 Y。另用首尾样例验证纵向夹取，断言新手势正常更新 `scrollTop` |
| C5 输入优先级 | 依次执行长按未成立前加第二指、已拖选区手柄时加第二指、未完成笔迹时加第二指、已启动的侧栏或宿主拖拽时加第二指、捏合后留一指扫动再释放。切到 PDF Text 执行已有翻页 | 待定正文动作让位于双指且无误提交，活动手柄和已启动拖拽继续独占，留下一指不会触发另一动作，Text 仍按原规则翻页 | 比较缩放、页/分栏状态、源选区端点及工具回调次数。验证已确认对象未被重复更新 |
| C6 清理与分栏 | 捏合中发 `touchCancel`，另轮分别切模式及更换 PDF。在双栏中对其中一栏捏合 | 取消收至最近稳定手势前状态，切换遵循新视图初始规则。只有起手栏缩放，新手势可正常开始 | 同时采样两栏矩阵、滚动量和原页号，确认旧手势不再更新。在 WebBase 复用已有双栏触摸夹具 |
| C7 包与集成 | 发布后查询 npm 精确版本和 dist-tag，WebBase 以两个锁文件冻结安装，再打开常规编辑器中的 PDF Layout | 两套安装解析到同一 registry 版本，`ham414` 指向本次包，`latest` 保持原值。常规路径加载 PDF 并通过 C1–C6 | 保存 `npm view`、dist-tag 前后值、依赖解析与 Playwright trace。常规入口检查 PDF viewer ready |
| C8 开发入口 | 在 WebBase 根目录执行 `pnpm webview:demo`，于 `?demo=1` 点击 PDF 缩放样例。另访问生产构建同一参数 | 开发入口一键加载多页 PDF Layout，能用同一包双指缩放。生产构建隐藏开发入口 | 开发页断言样例按钮、viewer ready 和 C1 的 2× 结果。生产页断言无样例按钮和 Demo 壳 |

真机仅验以下两项。行为几何以 Chromium 数据为准。

| 白名单 | 操作步骤 | 期望与判定 | 浏览器缺口 |
| --- | --- | --- | --- |
| D1 原生 WebView 触摸透传 | 在实际交付平台的 WebBase 开发构建打开 WebView PDF Layout，在栏内连续捏合、平移、释放并重复 | 页面 PDF 能缩放和平移，宿主没有全页缩放或拦走手势。记录平台、构建号、版本及屏幕录像 | Chromium CDP 无法经过 WKWebView 或 Android WebView 的原生手势识别器和宿主事件分发 |
| D2 原生导航栏 | 在同一入口靠近原生导航栏操作正文缩放，结束后点原生返回，再次打开 PDF | 缩放期间导航栏无误触且保留可操作，主动返回只触发一次。以录像并核对返回前后页面判定 | 浏览器开发宿主和 Expo Web 均无真实原生导航栏及导航栈 |
