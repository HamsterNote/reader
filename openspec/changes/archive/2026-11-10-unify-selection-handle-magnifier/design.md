# Design

## Context

动机见 proposal.md。当前仓库使用 OpenSpec 1.13.1、spec-driven；没有进行中的 change，也未发现仓库自带的 propose 命令或技能文件，因此按已安装 openspec-propose 与 CLI 实际返回的模板执行。

只读检查发现：

- `EngineSelectionControls.tsx` 的 PDF 路径保存抓取 offsetX/offsetY，并以命中后的 Range 坐标推动镜片；非 PDF 路径拒绝 touch 手柄按下。必须将指针位置与字符端点拆开。
- `RangeMagnifier.tsx` 有 PDF 文字复制及其他页面截图两条路径，move 会调度截图，PDF marker 只更新颜色与高度；CSS 默认把 marker 固定在镜心，非 PDF 仍为圆点。
- `rangeMagnifierGeometry.ts` 使用 120px 镜片与 18px 边缘间隙，当前镜心到手指约 78px，并非需求中的约 1cm。
- `TextSelectionMagnifier.tsx` 记录到手柄中心的偏移，且注释及现有测试明确允许选区层在拖动开始后移除手柄。`useRangeHandleDrag.ts` 也存在抓取偏移，需只针对本次文字手柄路径调整，不能误改矩形工具。
- 现有 PDF 规格明确“镜片位于手柄之上”和“命中按行内位置纠偏”；EPUB 规格仍声明触摸原生范围调整。delta 将完整保留受影响 requirement 的其他场景，修改冲突语句并引用唯一共享规范。

## Goals / Non-Goals

**Goals:** 将原始指针、逻辑插入端点和镜片显示坐标分离；让三个渲染面以同一会话及显示规则接入，保留引擎字符映射。针对用户第 2、4、5 条形成可重复验证的输入、几何和渲染证据。

**Non-Goals:** 不更换阅读引擎、不改变标注格式或宿主协议，不统一各模式原有滚动与跨端交换规则，不改矩形/绘图手柄，不在 propose 执行实现或真机验收。

## Decisions

### 1. 唯一规格与薄适配

新增 `reader-text-selection-interaction` 承载全部共享条目；PDF 与 EPUB delta 只调整现有冲突和引用，不复制三份规则。PDF、EPUB 继续负责各自命中、源字符范围及提交，向共享镜片传递当前指针、插入间隙几何、操作目标有效颜色及文字来源。

曾考虑分别补全三份规范，但会产生漂移；也不把 PDF 的跨页自动滚动带到按钮分页模式。原生初始选字可保留，之后由受管手柄提供一致的拖动反馈，避免原生放大镜成为另一套表现。

### 2. 拖动会话同时保留指针与字符锚点

会话由稳定的 viewer/document 持有 pointerId、pointerType、原范围及最新有效范围；只有 touch 且开关开启才启动镜片，镜片 API 的所有文字入口都执行这一条件，避免一个入口漏检。可见手柄保持挂载或在稳定叠层渲染，不能依赖已被选区库移除的 DOM。

实际命中仅用原始 clientX/clientY 经既有 iframe、页面、变换换算，不叠加圆柄中心、端点中心或避让偏移。pointerup 使用最后真实位置完成既有合法性判断，不等待下一动画帧；取消、失焦与会话替换统一释放监听、捕获、镜片和预览。扩大热区只扩大启动范围，按下本身不提交范围修改；后续移动和释放按实际落点判断。

备选的“保留 offset 但只对镜片消除”无法满足指哪行选哪行，故不采用。无效范围及端点交叉按各格式既有契约处理。

### 3. 连续镜片与离散竖线分开更新

镜片显示位置只取原始触摸点；字符命中无变化也移动取景。竖线先绑定源字符间隙，再通过取景的同一放大与平移映射到镜内，不固定居中、不对端点插值。取景连续移动时竖线与原字符边界共同移动；只有源端点跨界才切到另一间隙。正文颜色与镜内颜色共用当前操作有效颜色解析：草稿跟随当前色，已有高亮范围编辑保留其原色，显式改色后更新。

备选的镜心竖线会在手指尚未跨字时滑过字形；对竖线加缓动会出现无意义的中间插入位置，均不采用。

### 4. 约 1cm 的工程口径（合理假设，未经用户单独确认）

Web 无可靠物理厘米测量，本提案暂以 CSS 参考像素换算：1cm = 96/2.54，取镜心垂直距离 38 CSS px，无夹取时验收容差 ±4 CSS px，不乘 DPR。三渲染面使用同一参数；真实设备需人工核对观感，不能把 CSS cm 声称为真实物理尺寸。

无边缘约束时镜心为 (x, y-38)，镜片完整放不下才取 (x, y+38)，横向及极小视口夹取至正文可见区域；边缘场景不以 38px 距离判失败。旧直径 120px 大于 2×38px，若直接保留会覆盖手指和手柄；拟将镜片直径调整为 60 CSS px，保留 2×取景倍率，保证正常布局下镜片下边缘与手指有约 8px 距离。直径属于本提案的设计取舍，评审可调整，但须保持镜心距离、可读性与手柄可见性。

### 5. 正文文字缓存与选区解耦

复用 PDF 纯文字复制路径；为 EPUB/PDF Text 提供同等的无选区文字来源，按当前可见文字和排版代际缓存，不克隆事件处理器、发布物可执行属性或整本内容。取景移动只重定位缓存；选区变化不触发重新截图或复制选区，镜内统一排除草稿填充、已有高亮、系统选区及手柄。独立竖线覆盖在文字上，正文选区仍实时更新。

跨页、滚动、文字层就绪、字号/布局变化允许按需要更新文字缓存，异步更新携带会话代际，旧结果不得覆盖新会话。备选冻结含选区截图会残留旧高亮；继续按 move 截图会把选区刷新耦合进镜片，均不采用。保留其他非文字工具的既有截图路径。

### 6. 验收与证据

复用 `test/engine-selection-controls.test.tsx`、`test/text-selection-magnifier.test.tsx`、`test/range-magnifier.test.tsx`、`test/pdf-magnifier-text.test.tsx` 及相关 geometry 测试，更新过时的“手柄消失仍继续”与鼠标可启动镜片断言。共享用例参数化三渲染面 × touch/mouse/pen × 起终点 × 草稿/已有高亮。另测未知输入与开关关闭。

浏览器层用 `demo/selectionHarness.tsx`、`scripts/check-web-selection.mjs` 和 PDF 现有检查脚本验证真实文字命中、iframe 坐标、缩放与高亮颜色；逐帧几何检查竖线锚点，不仅检查最终截图。对同页稳定排版的一段拖动记录镜内选区刷新/重截图次数为 0，同时确认正文选区更新和镜片连续移动；跨页文字更新单独分类。iOS/Android WebView 真机验证系统选择 UI 抑制、混合输入、手柄常显及边缘翻转，未执行项明确标为待验，不以桌面模拟代替。

## Risks / Trade-offs

- [第三方选区库在拖动中移除手柄] → viewer 持有会话并以稳定受管层显示真实端点；优先适配现有公开能力，不在本提案预设依赖升级。
- [小镜片可读性下降] → 以约 1cm 镜心约束选择 60px 直径，真机核查 2×文字可读性；尺寸调整不得破坏手柄常显。
- [离散锚点被误判为镜内像素固定] → 验收比较源字符边界和投影误差，而非要求竖线像素不动。
- [排版变化、滚动或迟到的文字来源导致错位] → 缓存绑定内容/几何代际，失效时重建纯文字来源；保留最新有效范围并沿用原取消策略。
- [范围编辑改色语义混淆] → 使用操作目标有效色，不把当前工具栏色无条件覆盖到历史高亮。

## Migration Plan

无需数据迁移。下一阶段先落地共享会话与几何，再接入 PDF/EPUB 文字路径和稳定手柄，完成自动化及设备验证后交付审核；若回退，仅回退该交互实现与相应规格变更，不重写用户标注。此处仅为后续计划，未执行 apply。

## Open Questions

无阻碍提案交付的问题。设备型号和系统版本由实际可用 iOS/Android 验收设备记录；约 1cm 的 CSS 换算和 60px 镜片尺寸为以上明确披露的提案假设。
