## 已实现

- 有效 EPUB iframe 选区显示默认 Popover；支持跨段落、strong/em/span、反向选择及旧字符偏移规则。草稿替换、已有高亮激活、端点编辑分别处理。
- 默认菜单使用引擎当前目标及内部范围数据；草稿改色不修改旧高亮，触摸 pointerdown 后的合成 click 不重复新增。

- 改色合并样式字段；受控删除等待宿主权威数据，内部模式更新自身数据。删除关闭操作目标并使已捕获的编辑、改色、删除回调失效。宿主拒绝删除而保留 ID 时，新的激活恢复操作，可以改色、重试删除；即使复用同一 DOM Range，旧回调仍不能操作它。
- 沿用现有撤销重做、公开 page-N/offset 与主线存储格式；未修改区块层、绘图实现或存储迁移。

## 用户书补修与固定回归

用户提供的原书 SHA-256 为 `cf8906cac0e68186069d5b3d85412675a7b45d58d7b53dac6b541321aaafa080`，共 9,685,904 字节。结构为封面章节和一个大型正文章节。原书文件继续保留在开发服务的 `ham138-dev-assets/user-book.epub`；回归清单 `test/compat/fixtures/epub/user-book-regression.json` 记录附件 ID、哈希、正文条目、旧坐标与字符总数。

定位到两个问题：

1. 旧文本管线按源码换行分行、逐行去空白后直接拼接；DOM 索引将 LF 当普通空白折叠，给 pre/code 等位置增加了空格。原书首差异为 offset 4232，DOM 流长 130692、旧文本长 128624，严格校验因此禁止整章定位。现在 LF 使用同样的行边界规则，静态 XML 与 Foliate 活文档均完整匹配 128624 字符；保留严格校验和历史偏移规则。
2. 恢复映射后，原实现每次选区/定位对整章逐字符调用 `compareDocumentPosition`。性能采样中约 3994ms/4240ms（94.2%）落在该原生调用上。现在利用字符 DOM 顺序二分查找端点；测试限制大章节单次选区的 DOM 比较次数小于 64，避免只验证文本一致却留下交互卡顿。

原书的 ASCII `OS` 确切端点 `page-3 / [4745, 4747)` 已固定在回归清单；原创样本固定为 `page-2 / [38, 40)`（源码前缀长度 15 + 14 + 9）。静态/活文档索引结果与最终高亮分别直接对照这些常量，避免由被测索引生成期望。沿用旧封面补页坐标，不将两个 spine 条目误当成只有两个逻辑页。已验证受控/内部两种模式的原生鼠标选择、菜单与颜色、草稿替换、跨段落高亮、已有高亮切换、端点修改、删除、撤销重做及保存重开。

常驻原创样本 `test/compat/fixtures/epub/large-code-section.epub` 包含 EPUB2/NCX、两个 spine、正文 1798 个段落、209 张图片及跨节点代码换行；由 `node scripts/create-large-section-fixture.mjs` 可重建，默认完整浏览器入口会运行该样本。原书按哈希固定，保留本地文件或从原 issue 附件下载后可重复执行：

```sh
node scripts/check-large-epub-selection.mjs ham138-dev-assets/user-book.epub
READER_USER_EPUB=ham138-dev-assets/user-book.epub node scripts/check-engine-interactions.mjs
```

浏览器用例先等待真实可见 iframe 与导航完成，再用鼠标输入选择；不会把初始化中零尺寸 iframe 的坐标当作有效正文位置。截图及 `large-epub-report.json` 随本轮补丁交付。OpenSpec 14/14 完成，4.4 根据人类验收与交付指令关闭，change 同步主规格后归档。

## 人工验收

使用现有宿主加载 reader，选文字工具并关闭自动高亮。开发网页可运行 `yarn dev --host 0.0.0.0`，打开 `/demo/selection-harness.html`；添加 `?uncontrolled` 对照内部模式。页面的 Snapshot 输出可检查 ID、端点和回调次数；正式 WebView 用宿主同样检查持久化数据。

1. 分别记录 iOS 和 Android 的设备型号、系统版本、WebView/Safari/Chrome 版本、reader 提交及受控模式。每项记录“通过/失败/未覆盖”和复现步骤；失败时附录屏与操作前后范围数据。
2. 正文长按，拖原生手柄跨两个段落和行内粗体/斜体；应出现选区菜单。先换颜色再点高亮，只新增一个 ID，颜色及规范化文本匹配选区。折叠选区后不应继续确认旧草稿。
3. 先长按得到 A，另处重新长按得到 B，再确认；只保存 B。激活 H1 后重新长按新文字并换色，H1 不变。
4. 点击 H1、H2，菜单及颜色应跟随唯一当前 ID。点击历史跨章高亮的当前可见片段，应留在当前章并操作完整 ID。
5. 激活高亮后，用系统原生手柄跨段落扩大终点、缩小起点；每次结束只更新一次，ID/创建时间/样式其他字段/评论关联及未编辑端不变。取消、失焦或端点交叉不写入；页边拖动不自动翻页。此项按本次人类验收结论记录。
6. 改范围后触摸删除，只删除当前 ID；快速切换目标、翻页、切书或随后到达的旧事件不能使其复活。受控宿主延迟回传时检查数据仍以宿主为准。
7. 对新增、改色、改范围、删除分别撤销重做；保存重开、调字体/窗口、切章返回后，完整端点与 ID 保持。PDF 同样回归菜单、新增、激活、范围修改、颜色与删除。
